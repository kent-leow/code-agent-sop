# Requirements-to-Code Workflow

Agent-driven pipeline: raw requirements → production code with full traceability.

## Pipeline

```
Raw Requirements
  → @generate-plan   →  plan.md  (re-run to refine)
  → @generate-task   →  task-001.md, task-002.md, ...
  → @execute-task    →  production code + tests
  → @fix-task        →  fix-{datetime}.md  (per issue batch)
```

Each stage produces artefacts in `.docs/<feature>/`. Nothing advances until prior output is verified.

### Greenfield (new app from scratch)

Detected automatically (empty repo / no app manifest / "from scratch" request / `**Project Type**: Greenfield` in `plan.md`):

```
@generate-plan  →  plan.md (feature inventory, users & roles, information architecture, platform constraints)
@generate-task  →  blueprint.md (stack + verified versions, envs, env vars, commands, route map, navigation) → STOP for approval
"approve blueprint" →  phased task-NNN.md:
   P0 Environment & Toolchain → P1 Backbone Scaffold → P2 Delivery Pipeline (CI)
   → P3 Cross-cutting Foundations → P4 App Shell, Routing & Navigation
   → P5 Features (walking skeleton first) → P6 Hardening & Release
@execute-task   →  one task at a time; app stays runnable after every task
```

Rules live in the `app-blueprint` skill.

## File Structure

```
.docs/<feature>/
├── plan.md              # Requirements, AC, open questions
├── blueprint.md         # Greenfield only: technical blueprint (Status: Proposed | Approved)
├── jira.json            # Jira story + sub-task keys
├── task-001.md          # Vertical slice 1
├── task-002.md          # Vertical slice 2
├── fix-{datetime}.md    # Isolated fix log per issue batch
└── figma/               # Cached Figma assets
    ├── context.json     # Design spec
    ├── screenshot.png   # Visual reference
    ├── summary.md       # Parsed summary
    └── flow.json        # UI flow (if applicable)
```

## Stages

| Stage | Agent | Input | Output |
|---|---|---|---|
| 1. Plan | `@generate-plan` | Raw requirement | `plan.md` + Jira story |
| 2. Tasks | `@generate-task` | `plan.md` (no blocking questions) | `task-NNN.md` per slice; greenfield: `blueprint.md` (approval gate) then phased tasks P0–P6 |
| 3. Execute | `@execute-task` | `task-NNN.md` path | Code + tests + checkboxes marked |
| 4. Fix | `@fix-task` | folder + issues | `fix-{datetime}.md` + fixes applied |

## Naming Conventions

| Artefact | Pattern | Example |
|---|---|---|
| Feature folder | `kebab-case` | `create-form-and-application` |
| Plan | `plan.md` | `.docs/create-form/plan.md` |
| Task slice | `task-NNN.md` | `task-001.md` |
| Fix log | `fix-{datetime}.md` | `fix-20260424-143000.md` |
| Jira state | `jira.json` | `.docs/<feature>/jira.json` |

## Integrations

| System | Behaviour |
|---|---|
| Jira | `generate-plan` creates story; `execute-task` creates sub-task; keys in `jira.json` |
| Figma | `generate-plan` creates `figma/` folder under plan folder; stores context.json, screenshot.png, summary.md, flow.json; reuses cached files on hit |

Requires: `JIRA_TOKEN`, `JIRA_EMAIL`, `JIRA_BASE_URL`, `JIRA_PROJECT_KEY`, `FIGMA_TOKEN` in `~/.zshenv`.

## Quality Gates

- Traceability: every task links to AC in `plan.md`
- Prerequisites: `execute-task` refuses if earlier slices have open items
- Greenfield: no tasks until `blueprint.md` is `Approved`; no feature slices before env/scaffold/CI/foundations/app shell; every route has a shell + owning task; every task has runnable `Verify` commands
- Test coverage: every logic task has a test child
- Changelog: every refinement appends dated entry
